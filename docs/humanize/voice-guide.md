## 2. Voice Principles

1. **Be Specific, Not Generic:**
   - Mention the actual tools, versions, and system topologies (e.g. "Spring Boot with stateless JWTs and S3 audio buffers", not "modern scalable backend").
2. **Be Honest About Trade-Offs:**
   - Real engineering involves constraints and trade-offs. If a real-time editor uses in-memory room broadcasting instead of database persistence to prioritize sub-50ms latency over durable history, say so directly.
3. **Imperfect on Purpose vs. AI Uniformity:**
   - Avoid boilerplate adjectives ("passionate", "cutting-edge", "game-changing", "seamless", "tapestry").
   - Use clear, plain declarative sentences.
4. **Respect the Academic Background:**
   - Frame the mathematics background as practical discipline: proving invariants, analyzing asymptotic complexity, avoiding unexpected state mutations, and handling edge cases systematically.
